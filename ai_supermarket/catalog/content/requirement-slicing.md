# 需求拆解方法

先写结果而不是按钮：谁在什么情况下需要得到什么。

对每条需求填写：触发 → 前提 → 输入 → 正常步骤 → 输出 → 失败处理 → 验收证据。
将一个大流程切成能独立验证的纵向切片，每片包含必要数据、权限、异常和结果，不按页面/后端单独算完成。
至少覆盖空输入、权限不足、依赖超时、重复提交与取消；无写入任务可说明相应项不适用。
排序为必须/应该/后续/不做；技术依赖写在对应需求旁。
验收使用“给定…当…则…”，避免“效果好、体验佳”。

反例：“完成支付按钮”不足以验收；应核对订单、授权、金额、真实状态及重试不重复执行。
