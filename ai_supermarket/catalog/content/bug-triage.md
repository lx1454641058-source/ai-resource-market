# 程序故障定位

适用：程序报错、行为与预期不一致。先获取复现动作、预期/实际、完整错误类型及最接近业务调用的堆栈、运行环境和最近变更；日志先脱敏，不索要密钥。

1. 在已有授权的开发环境重现一次，记录输入和结果。生产写入、真实付款、删除数据等不可为了复现而执行；先构造最小本地输入。
2. 沿“输入→解析→业务判断→外部依赖→输出”定位最早偏离预期的一步。报错行是观察点，不自动等于根因；检查其上游数据类型、空值和约束。
3. 写不超过三个可区分的假设，每个配一个只改变单一条件的检查。先做低成本且能排除最多假设的检查，不同时改多个参数、升级依赖和重写模块。
4. 用最小改动修复已证实原因，保留原失败输入作为回归用例；同时检查相邻边界和错误返回。原问题不能再复现不等于所有环境都已修复。
5. 若无法复现，交付已检查事实、未证实假设和下一条需要的数据；不要编造根因或标记修复完成。

示例：计算总价报“字符串与整数不能相加”。检查进入累计逻辑的数据类型；若金额来自CSV文本，先明确金额解析与缺失规则，再在输入边界转换，不能用捕获所有异常并跳过订单掩盖问题。

交付：触发条件、根因证据、修改位置、复现前后结果、未验证环境及回退方法。
