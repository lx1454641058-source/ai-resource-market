# 网站内容与页面结构

适用：落地页、介绍页、服务页面尚无清晰内容结构。先确认受众、他们要完成的一个主要动作、已证实信息与品牌约束；不直接从视觉风格反推业务承诺。

1. 首屏给出“服务谁、帮助完成什么、下一步做什么”。主按钮要对应真实可用动作；报名入口尚未存在时，不制作会假报提交成功的按钮。
2. 按访客决策顺序组织：核心说明→使用场景→依据或案例→流程/价格条件→常见问题→行动入口。缺少真实案例、价格或客户时明确留空，不能编造数字、评价和商标。
3. 每个区块只回答一个问题。标题直接说明内容；链接文字说明目的地；表单字段有可见标签，并给出成功、失败、空内容和加载状态的真实行为。
4. 先用内容线框确定层级，再做样式。复用现有组件，检查窄屏文本换行、长按钮、图片比例、键盘焦点与主要操作是否可达。
5. 点击每条主路径，核对跳转、提交和错误状态。效果图、静态页面、真实服务三者分开标记；上线和数据收集按实际授权执行。

示例：预约服务还没有后端。可以展示真实联系方式或说明预约入口未开放；不能点击后提示“预约成功”而没有保存或通知。

交付：页面区块表、已有/待补内容、主路径、状态行为及实际检查记录；不默认需要新框架或外部依赖。
