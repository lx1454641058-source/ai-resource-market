## 2. 推荐先核实的资金路径

**优先核验候选：买方付款给商品卖家，由具备资格的渠道把约定佣金分给平台。** 这是基于角色清晰度的产品建议，尚不是已支持或已批准的方案。个人/企业卖家、平台主体、商品类别、分账产品、比例限制和退款权限必须一并取得适用证据。

| 候选 | 必须先获得的证据 | 不满足时的处理 |
|---|---|---|
| 卖家为原收款商家，平台接收10%佣金 | 各卖方类型准入、Machine Pay 与分账兼容、平台接收资格、退款冲回、对账与费用规则 | 对不支持的类型保持免费获取；不擅自换成个人转账或平台代收 |
| 平台收全款，再分给卖家 | 平台交易/收款资格、多卖家授权和全部售后路径；尤其核实个人分账接收方退分账限制 | 不作为默认路径。即使收款成功，退款未闭合也不开通 |
| 直接使用 SkillPay 的销售链路 | 第三方市场接入、权益交付和平台收费是否允许，如何防止重复采购 | 若无法保留已确认商业规则，作为替代方案供业务负责人比较，不默认为本平台实现 |

“个人作为分账接收方”与“个人作为原收款商家”是不同关系。现有资料不能确认任一主体已经符合条件，也不能以变换名称规避渠道要求。

10%比例、免摊位费、自主定价、非强制参考是已确认规则。计佣基数、分币舍入、渠道费承担、结算周期与退款后的佣金调整仍依 D-06；本文不批准新的收费条件。第9.1节的净额计佣与累计舍入仅作待审计算草案。

## 3. 技术实现前需要冻结的契约

契约是双方约定的字段含义与成功、失败判定标准。以下是本项目拟定的验收要求，不是已实现能力。

- **金额：**内部商品订单沿用整数分；对每个实际渠道接口分别记录币种、单位、字符串格式、舍入和最大值。金额疑点未澄清前不生成真实账单。计量中的百万分之一元不直接发送给支付接口。
- **订单：**报价冻结卖家、商品版本、许可、金额、币种、有效期与业务订单号。将渠道交易号唯一关联至原订单；买方给出的字段不能更换收款主体或扩大权益。
- **付款证明：**可信校验结果与原订单相符后才改变付款状态；请求超时、凭证失效、响应丢失时先核原订单，不能据此自动创建第二笔付款。查询接口及其对 Machine Pay 的适用性也须确认。
- **交付与履约：**付款已确认、资料可取用、履约回执完成分别记录；履约确认重试不能重新扣款或重复发放权益。已购静态商品在许可内复用，不重新购买。
- **退款：**依适用产品规则判定结果；同一退款请求保持原编号和金额。对结果未知、部分退款、已结算和余额不足分别保留处理状态，不能仅因请求受理就冲减账目或宣称完成。
- **分账：**佣金金额正确不等于渠道分配成功；记录接收主体、授权、分账状态及退分账状态。相关资格或回退能力未核实则拒绝启用对应付费路径。
- **对账：**订单、支付、退款、佣金、渠道费用、卖家实收逐项对应真实凭证；未知不得填零。生产凭据和完整付款凭证不进入模型上下文或普通日志。

## 7. 报价到渠道订单的绑定准备（v0.80，2026-09-23）

本轮重新读取[Machine Pay指南](https://aipay.alipay.com/docs/ai-receive/MACHINE_PAY.html)及[支付凭证验证API](https://aipay.alipay.com/docs/ai-receive/api-list/alipay-aipay-agent-payment-verify.html)，页面显示更新日期为2026-09-22。金额字段仍有“最小货币单位”与0.01示例之间的口径疑点，未据此转换元/分。API声明resource_id最长32字符，而超市商品编号可更长；不能直接截断原商品编号。渠道验证返回业务成功、有效凭证和订单字段匹配后，仍需本地持久化关联及防重复履约；文档不证明项目已获得相应资格。

[官方常见问题](https://ideservice.alipay.com/cms/site/0j7uos)明确service_id来自服务开通资料且审核成功后生效。代码中的fixture标识是原创测试占位，不能替代真实服务审核。已看到官方指南链接到alipay/ai示例仓库，本轮未安装、复制或执行其代码，未确认示例许可并据此分发。

新增[可信宿主示例machine_pay_order.py](../examples/machine_pay_order.py)，只读现有Exchange报价，不增加市场公开工具、HTTP路由或数据库表：

```python
from ai_supermarket.examples.machine_pay_order import prepare_order, recheck_order

# buyer_market是可信宿主持有的买方实例；merchant_mapping来自宿主配置。
# 原发行摘要来自选品阶段，不能在变更后静默换成新值。
prepared = prepare_order(buyer_market, quote_id, original_release_digest, merchant_mapping)
# 宿主保留完整prepared后，恢复时重新核对；此调用仍不授权支付。
same_order = recheck_order(buyer_market, prepared, merchant_mapping)
```

merchant_mapping包含market_id、market_seller、seller_id、app_id、service_id和environment（sandbox/production）。它是宿主声明，不能来自模型或商品正文，不能证明真实渠道关系；选production也不会启用支付。market_id须稳定对应同一市场，映射到哪家收款商户及应用须另核实。

准备步骤在同一数据库读快照中核买方报价、有效期、商品状态、版本与发行摘要、用途、报价修订、价格、费用规则、宿主兼容性及已有权益。返回整数分、完整绑定摘要和两个不超过32字符的渠道编号；同一记录在新进程及不同JSON字段顺序下得到同样编号。商品、主体、环境、价格或绑定记录变化时停止，不覆盖旧记录。免费商品无需准备付款；同用途版本已有权益时提示复用。
