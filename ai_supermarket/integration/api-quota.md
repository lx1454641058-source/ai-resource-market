# 供应商 API 次数账本

2026-09-23，v0.101，本项目原创。`api_quota.ProviderQuota` 是供应商内部组件：把已经获得、由供应商独立确认的调用权益转换为有界次数，记录原请求和结果。它不收款、不签发权益、不提供公共 HTTP 或模型工具。

v0.102已通过[API商品与本地交付](api-product.md)连接正式API元数据、市场原权益和本地结果文件，v0.103新增[远程API任务入口](api-remote.md)；普通文本权益不能作为API套餐。真实供应商和真实支付尚未接通。下面仍描述本组件自身的供应商计量职责，不能单独证明付费API已商业可售。

## 权限与调用位置

可信供应商网关认证用户后，提供 `principal`，并调用 `invoke(principal, request, execute)`。这些都是 Python 内部方法，不是允许模型指定回调的接口。`authorize`、`execute`、`lookup` 必须由供应商配置；不能取自用户提示、商品内容或未审查代码。

构造方式：

```python
from ai_supermarket.api_quota import ProviderQuota

quota = ProviderQuota(private_ledger_path, provider_id, authorize, require_existing=True)
reply = quota.invoke(authenticated_principal, request, execute)
```

`private_ledger_path` 必须指向该供应商独立、持久且受保护的本机 SQLite 文件。所有服务实例必须使用同一账本，不能每次请求创建新账本来重置额度。不支持网络共享文件系统上的分布式账本。本组件不升级或迁移现有市场库；若已有其他表或供应商绑定不符则拒绝打开。备份、访问权限、持久存储及恢复仍由部署方负责。

v0.125区分首次初始化与重新打开：仅在可信准备流程中首次创建新账本时使用默认的 `require_existing=False`；服务重启或请求内重建宿主时必须传 `True`。`ApiDeliveryHost` 对应参数为 `require_existing_ledger=True`，已交付的API网关与演练服务使用该模式。已有账本缺失、空文件或缺少表时拒绝打开，不初始化替代库；运行期间每次事务也只打开现有库，文件检查后被移走时不能自动创建新库。没有SQL结构迁移。

账本丢失时先停用新调用，由运营核查并恢复原记录，不能复制空库、清空占用或换请求编号继续。执行后丢失账本可能已有上游费用；恢复原记录后保留原占用，通过原操作查询核对，不自动重发。本检查不识别用合法格式的旧备份替换当前库，不能替代持久存储、备份时点核验和独立对账。

请求字段固定如下，没有 URL、支付声明或用户指定次数：

| 字段 | 来源与用途 |
|---|---|
| acquisition_id | 已核验的原权益编号 |
| resource_id、version、release_digest | 原商品、版本及发行摘要 |
| purpose | personal_use 或 commercial_use |
| task_id、request_id | 原任务及调用编号，重试保持不变 |
| operation | 已获准的供应商操作名称 |
| input | 操作的 JSON 对象输入 |

整个请求最多16 KiB。授权器签名为 `authorize(principal, request)`，每次执行、状态查询、恢复和缓存返回均调用；执行完成后还会再次调用。它必须查可信权益记录，独立确认身份、付款来源（收费权益）、原版本与许可用途、任务权限、操作范围、输入字段及有效期。拒绝时抛出 `MarketError`，不能仅比较模型传来的 `paid=true`。

通过后授权器返回稳定的声明：`provider, principal, acquisition_id, resource_id, version, purpose, release_digest, operation, total_units, expires_at`。除后两项外必须精确匹配认证主体、当前供应商和请求；`total_units` 为1至1,000,000整数，`expires_at` 为UTC Unix秒。以上限是工程边界，不是定价建议。次数和期限须源于供应商已确认的原权益，不能按请求随意填写。

同一供应商、主体和 acquisition_id 只能绑定一份不可变声明；修改额度、期限、版本或操作不会重置原账本。多个任务共享该权益的总次数。追加权益、多操作共享套餐、包月、按字节计量和按次后付费暂未实现。

## 调用、结果与恢复

本版每个新请求占用1次，不根据返回行数追加扣量。事务中先检查剩余额度，再保存 `reserved`，提交后才调用供应商执行器。供应商执行器签名为 `execute(operation_id, operation, input)`，必须把稳定的 operation_id 传到实际原站工作记录，用于查询与防重。执行器自身也不能隐藏重试收费动作。

正常返回是有界 JSON 结果，最多64 KiB；账本保存原结果及其SHA256，状态变为 `completed`。这里的完成仅指该 API 调用，`task_completed=false`，不能当成用户最终成果。返回给可信宿主的 `result` 尚未封装成低Token的文件交接，未来模型入口应返回小摘要/句柄，按需读内容。

相同主体、任务、request_id 的相同请求不会再次执行；改输入、操作或权益会被拒绝。新请求编号代表新的调用，仍消耗总额度。重启从同一账本恢复。并发相同请求只会有一个执行者，并发不同请求不能超过剩余次数。

| 状态 | 额度处理 | 下一步 |
|---|---|---|
| reserved | 占用1次 | 查询原供应商调用，不自动重发 |
| completed | 使用1次 | 复用原结果及摘要 |
| not_executed | 不计入占用或已用 | 原请求为终态，不重新执行 |

返回 `reserved_units, used_units, remaining_units` 是该原权益的当前汇总，不是金额或付款账目。调用异常、响应丢失、结果超过上限、过程退出或后置权限校验失败均保留占用。异常原文不返回，避免泄露供应商凭据；模型也不能据此判断“没有扣费”。

显式恢复调用 `recover(principal, request, lookup)`。`lookup(operation_id)` 必须查询原供应商权威工作记录，属于只读操作，返回：

```json
{"state":"unknown"}
```

或 `{"state":"completed","result":{...},"evidence_ref":"原站证据编号"}`。只有供应商能够证明该操作确定未执行，并阻止所有已排队/在途任务将来执行，才可返回 `{"state":"not_executed","evidence_ref":"终止并核验的证据编号"}` 并释放次数。单纯“查不到”、超时、没有本地结果都不能当成未执行。`evidence_ref` 是可信查询器的记录引用，字符串本身不构成独立支付或执行证明。

恢复不会派发新工作。若供应商不能提供可靠查询，应保持 `reserved` 并交运营核查。组件不做自动过期释放、不回收未知占用，也不提供模型可调用的“确认失败并退款”。已失效或撤销的权益拒绝返回结果和恢复，后续运营侧对账及过期争议处理仍需单独接入。

## 正式市场衔接状态

1. v0.102已新增可审核的API商品契约，声明提供方/操作、输入结构、次数、期限与输出上限；使用原许可和独立v4契约，不套用 `origin_file`。
2. v0.102已新增市场原权益授权器，核原发行与付费来源；真实提供方的独立信任和商业授权仍需核验，不得使用测试授权器替代。
3. 可信宿主可固定任务、提供方与传输授权回调，保存结果和原许可证；v0.103新增默认关闭的认证HTTP接口、客户端接收和MCP任务模式，尚未公开部署。
4. 仍需把远程结果交还用户AI继续实际任务，并完成真实资金与次数的独立对账。不得把取得商品或组件测试当作用户任务完成。

当前测试使用原创虚构权益及本机HTTP服务。覆盖共享次数、并发、缓存撤销、有效期、同编号冲突、结果完整性、丢响应恢复和不迁移他库。真实商户、钱包、供应商权利、实际资金及生产运维尚未接入。
