# 既有模型调用与任务预算、用量记录联动

来源：本项目原创。此适配复用项目的 `steward.codex_model.CodexModel`；不安装模型、不修改账户认证、不授权账户消费。专项验证使用进程替身，未证明实际账户费用或产品收益。

## 接入位置与调用顺序

`MeasuredCodexCalls` 是供受信宿主使用的 Python 接口，不能作为商品代码或买方自由调用工具。宿主是管理 AI 任务、工具和权限的程序。已获准的模型调用可由本接口包装；选择商品仍由调用方 AI 完成。

依次为：冻结请求与实际提示摘要 → 任务预算预留 → 领取一次执行权 → 计量库记录调用 → 既有模型调用 → 校验完成记录及用量 → 费用未知并保留预留 → 获得实际费用依据后核销。相同请求编号不能换任务内容、模型、提示、输出结构或最大预留额。相同请求重放不再次调用模型，也不自动重放正文。

由宿主准备已存在且归属正确的 `model`、`meter` 和 `task_budget` 后：

```python
from ai_supermarket.codex_meter import MeasuredCodexCalls

calls = MeasuredCodexCalls(model, meter, task_budget)
# 下列操作会调用已登录账户。仅在实际调用已获准时执行。
outcome = calls.run(request_id, 'chat', context, maximum_micro_cny)
if outcome['status'] == 'completed_cost_unknown':
    artifact = outcome['result']  # 宿主负责按已批准的保存策略持久化成果。
    call_id = outcome['call_id']
    reservation_id = outcome['budget']['reservation_id']
```

支持既有纯文本 `chat` 和 `project_manager` 角色，不开放网页、脚本或商品依赖执行。既有适配固定 medium 推理配置，不接受伪报其他配置；调用方可设置 `CodexModel(timeout=...)` 限制等待时间。超时不证明没有账户用量。预算是软件准入上限，并不能强制供应商以此价格结束推理；真实费用超出预留时如实记录并暂停后续支出。

同一个模型对象应由一个包装器独占；不要绕过包装器直接调用、在执行中修改配置或在多个包装器间共享对象。单包装器串行执行，排队结束后才核预算。不同宿主可用各自模型对象与同一持久账本竞争同一请求，预算记录确保最多一次准入；这是防重复机制，不是保证一定完成。已准入调用不会因随后暂停自动取消，暂停限制后续调用。

## 用量、费用和结果分别记录

- 只读取既有适配器的完成记录，不相信模型正文中声称的 token 或金额。Token 是模型处理文本的计量单位。
- 必须只有一个明确完成事件。多事件的累加或累计口径尚未验证，拒绝将最后一条当完整用量，费用仍保持未知。
- 缓存输入是总输入的子集，不重复相加。缺失用量保持空值；独立推理输出计数非零时，因与输出计数是否重叠尚未核实，规范化输出总量保留未知。
- `completed_cost_unknown` 表示模型响应及用量记录完成、人民币费用待核，不代表最终任务质量合格。`provider_bill_verified=false` 始终明确本接口不验证供应商账单真伪。
- 调用记录保存任务、状态、用量与关联编号，不保存输入、正文、完整提示或异常文本。输出在返回前发生故障时可能无法恢复，宿主应核原请求，不能为找回正文自动另起收费调用。

官方[非交互模式说明](https://learn.chatgpt.com/docs/non-interactive-mode)列出完成事件及用量字段，支持读取调用结果；它不提供本项目的人民币账单核验。具体 CLI 版本及真实计量一致性需在获准试点中固定并复验。

## 费用核销与故障恢复

实际费用到达后，由受信操作方使用原编号补记：

```python
calls.record_cost(reservation_id, call_id, actual_micro_cny, evidence_ref)
```

`actual_micro_cny` 为百万分之一元整数，`evidence_ref` 指向受控账单明细，不放密钥或正文；示例不提供猜测金额。函数核任务/主体和调用关联，但证据内容仍由操作方核实。计量表的 `codex-host:<call_id>` 是宿主用量引用，供应商费用依据保存在相应预算预留的审计记录，通过 `codex-budget:<reservation_id>` 关联。

| 故障 | 实际状态与处理 |
|---|---|
| 额度不足、任务关闭、预算暂停 | 不执行新模型调用；修正授权条件后按原请求核查 |
| 预留后计量库写入失败 | 模型可能尚未执行，仍保守保留未知占额；核实后按既有预算管理流程处理，不能自动填零 |
| 模型超时、完成记录不匹配或用量损坏 | 标未知并保留占额；相同请求不会重试 |
| 用量落库失败或记录未知也失败 | 可能保留 succeeded 但缺用量，或 in_flight；都不是完整费用证据。原异常保留，持久预留继续占额 |
| 费用先写入预算、随后写计量失败 | 两账本不是一个事务；用同一预留、调用、金额、凭据再次核销可补第二笔写入，不再次调用模型 |
| 已知费用与补记冲突 | 拒绝覆盖，进入人工核账；不能换编号掩盖差异 |
| 程序重启、响应丢失 | 重建相同任务对象，按原请求查询对应 call_id；返回 not_executed，不表示上次未发生调用 |
| 快照恢复 | 沿用计量恢复门与旧任务冻结要求；恢复旧任务不得继续调用，先按[恢复说明](recovery.md)核原记录 |

模型完成只完成整任务中的一环。搜索、正文加载、其他调用、检查、反馈及失败成本仍由整任务宿主记录；不可因一个模型回执完整就将 `coverage_complete` 设为 true。最终产物另作独立验收，参见[整任务计量](measurement.md)。

## 有限故障诊断（v0.33）

模型进程失败可通过`CodexProcessFailure`提供固定字段摘要，试点保存为`failure.json`的`model_diagnostic`；详见[试点说明](pilot.md#失败诊断的范围)。该异常继承原`ModelUnavailable`，既有调用方仍可按原类型处理。

诊断保留错误类别和有限的控制事件计数，不保存正文、会话标识或stderr。它不是完成回执，也不提供可信用量或费用，不能触发预算释放或自动重调。哪怕超时前看到turn.completed，仍须通过原完整回执路径验证结果，未知继续保留。原v0.32失败当时没有保存事件，不能用新增功能倒推根因。

## 验证范围

专项位于 `ai_supermarket/tests/test_codex_meter.py`：覆盖进程契约到资源取用/模型/反馈链路、用量未知、重放与并发、预算暂停、异步到达的费用、双账本部分写入、异常保留、重启、跨任务及超支。全为合成输入与进程替身，不执行真实模型或支付。未证明所有宿主兼容、全平台额度、供应商账单认证、实际节约或生产运行。
