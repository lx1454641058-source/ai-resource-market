## 资源站只需先准备这些信息

已有JSON查询接口的网站可复用[固定原站适配器](provider-json.md)，按已审核商品声明映射参数并接入业务结果检查，继续沿用供应商授权与持久操作库。

需要直接启动供应商服务时，按[配置式接入](provider-service.md)准备原商品、身份、固定接口与结果规则，再分别执行prepare/check/probe/serve；不会自动上架或代替买方连接配置。

| 信息 | 给谁、何时使用 |
|---|---|
| seller、稳定source_id、slug、version | 清单对应原站和超市商品；保留原编号用于更新及核对，不能把名称临时当唯一标识。 |
| title/summary/keywords、输入/输出、样例 | 搜索只投影少量摘要；完整字段交prepare检查，不要求AI重写整个目录。字段名以商品契约为准。 |
| price_cents、allowed_uses、license_text、source_statement、usage_contract | 卖方自定价格和权利范围，免费同样须说明许可；审核查真实依据。默认佣金不代替具体报价/协议。 |
| 静态正文、素材文件、origin或api声明 | 按实际类型选择交付契约。原站文件声明固定字节摘要、大小和媒体类型；API声明操作、输入、次数、期限及结果上限。不要混用。 |
| 获准市场端点、身份凭据路径、提供方连接与发行白名单 | 由可信接入程序持有，按所需类型配置；连接密钥、Token不放清单、模型或报告。 |

正文和许可原文只在需要审核/取用时读取；批量工具返回短报告。API大结果落文件，AI只读实际任务所需部分。客户端默认每任务24次网络尝试，查状态和失败也计入；这不是模型Token或人民币预算。真实成本收益尚未测得。

## 一次试用怎样验收

先保存真实任务目标、实际用途、允许传输的数据、成果验收项和已获准费用范围。再记录：宿主是否自动初查、选中商品与发行、实际交付路径及许可、成果验收结果、需要的人工帮助和失败位置。没有选到合适资源也保留原因，不强迫消费。

身份撤销、输入错误、结果未知或文件冲突时保留原请求与记录。支付未知查原采购，API未知查原调用；不要删状态、改摘要、重发执行或重新购买来跑通。逐次回执不是成果质量、整包履约或支付证明。

收费路径已有上架、报价、宿主付款交接、权益与文件/API交付工程实现。当前MCP任务入口没有钱包执行器；付款须由已获准的可信宿主接上实际渠道。项目已有支付宝适配源码，但经营主体、商户/钱包、真实支付及退款分账对账尚未完成，免费样例不证明商业可用。未采用任务入口的AI也不能保证每次访问超市。

已有原退款的商户宿主可接续[退款状态查询](refund-query.md)，按原交易和退款编号核对签名结果；它不发起退款、不自动撤权或结算。该接口资格须单独核对，不能从Machine Pay连接推导。

成功观察可交给[退款记账与访问处理](refund-reconciliation.md)，由明确的宿主决定保留或停止后续访问，沿原费率计算累计佣金调整建议。实际退款、资金分账及完整渠道对账仍未完成。

可信本地运营者可通过[只读运营入口](operations.md)查看原订单、退款记录及佣金建议；该入口不联网、不提交退款或执行资金分账，也不开放给普通买家工具。
