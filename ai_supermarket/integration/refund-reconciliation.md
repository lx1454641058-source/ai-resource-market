# 核验退款后的记账与访问处理

v0.119，2026-09-23，本项目原创。可信宿主的 `PaymentRefunds` 消费[原退款查询](refund-query.md)已经保存的成功观察，累计本地已处理退款，并计算原成交费率下的佣金调整建议。它不提交退款、不转账、不执行分账，也不会恢复任务消费预算。

## 接续原订单

```python
from ai_supermarket.payment_refunds import PaymentRefunds

# query_client 是原订单的固定 AlipayRefundQueryClient。
# enabled 仅启用本地处理，不授予渠道退款或网络权限。
refunds = PaymentRefunds(query_client, enabled=True)
report = refunds.reconcile(
    order_id, refund_id, refund_cents,
    rights_action=operator_rights_action,
    decision_reference=operator_decision_reference,
)
current = refunds.status(order_id)
```

三个原编号/金额来自实际退款记录；金额单位为人民币分，必须与查询已确认的金额一致。处理决定和依据编号来自有权经营方依据资源约定作出的真实决定，不能让模型、商品正文或查询成功状态自动代填。该类是宿主内部接续组件，没有新增模型工具或远程HTTP操作。

| rights_action | 行为 |
|---|---|
| preserve_access | 记录退款，保持原访问条件；不重新发放、不增加API次数，也不能解除此前的停止决定。适用于有真实保留使用权依据的补偿等情况。 |
| block_future_access | 停止该订单的后续发放和访问，包括原正文重读、采购恢复取用、API新调用及通过超市重读结果。保留原付款、权益、用量和交付证据。 |

全额或部分退款都须明确选择处理动作，没有推断授权的默认值。部分退款不自动按金额比例扣除API次数；需要部分权益调整的业务尚不能通过本模块表达。已下载文件不会被删除，已发送到供应商的调用不能保证撤销；调用与退款并发时，发出前的检查不能撤回已经开始的外部动作。已有API流程在交付前还会重新检查权利，原未知调用须核对，不能重新执行。

## 重放、证据与恢复

只有固定HTTPS、原订单/主体/金额、原公钥验签均匹配且退款成功的观察可处理。`test_response`、未知、未确认、无查询记录均不写退款账。处理过程只读保存的查询，不新增网络请求或模型调用。

同一退款编号仅累计一次；同一编号重放需保持金额、来源和处理决定完全一致，更改动作或依据会拒绝。不同退款编号累计不得超过原付款，并发处理仍受同一事务约束。单订单最多1000条处理记录，达到本地上限后保留原账核对；这不是支付宝限额。当前不提供自动修改既有决定或恢复访问的入口。

处理记录及原订单内的 `refund_ledger_sha256` 摘要在同一个数据库事务写入。写入中断全部回退，成功但回复丢失则重放原编号；不删历史、不重新退款。访问前核对摘要、原查询成功观察和订单归属；记录缺失或损坏停止访问。这里的摘要只检测记录不一致，不是防止拥有数据库写权限的人伪造整个账本的独立安全证明。

停止未来访问不抹除历史付款或交付：原订单、退款查询、退款状态仍可查询，已存在交付的渠道回执仍按原规则核对。渠道回执只描述已发生交付，不表示退款后仍有使用权；本模块不会自动发送它。

## 佣金核对口径

`recorded_refund_cents` 仅为本地已处理退款之和。没有接入的退款可能未记入，`channel_refund_total_known=false`；它不是渠道整单对账已完成。佣金沿用原付款确认中的费率，不采用当前供应商新协议。按累计剩余金额取整，再计算相对原金额的累计冲减，避免逐笔小额退款产生舍入偏差。

`accounting_proposal` 返回剩余净额、平台佣金、卖方其他费用前金额和累计冲减建议。示例：原付100分、费率10%，先退15分，剩余平台佣金9分；再退15分，累计退款30分，剩余佣金7分。这些只是项目规则的计算，不是实际到账、退款或分账。渠道费用保持未知，`commission_settled=false`、`funds_moved=false`、`budget_restored=false`。

## 部署与工程验收边界

默认不启用处理。复用原meta表，无SQL结构迁移，但已处理订单会增加内部摘要字段；旧版本程序不支持该字段。不要将已处理账本切回旧程序来绕过停止访问。停用新的本地处理不解除已有停止决定；出现问题保留当前账本并排查，可用旧候选和独立旧账本复现，不覆盖现有账本。

测试使用隔离原订单和合成签名，覆盖正文、实际本地API调用与文件、首次发放、重复/并发、故障回退、原费率及身份隔离。真实经营资格、退款执行、商户到账、佣金实际分账、退款合同与真实供应商接续仍待验证。
