# 市场侧API连接配置

> 已有付费采购授权时，可另按[采购连接配置](purchase-connections.md)接入HTTP服务；同一凭据的采购与API用途必须一致。API连接本身仍不授权付款。

本项目原创，v0.126。市场运营方可使用已有API工具与任务预算，将已约定的供应商连接接到通用HTTP启动器。供应商侧使用[配置式服务](provider-service.md)或自行实现[原操作协议](api-provider.md)。不再要求修改固定演练代码；不创建买卖方身份、授权任务、批准商品或启用真实支付。

## 准备条件

- 已有市场、身份、预算账本；买方凭据编号已绑定获准的主体、根预算和任务。需要已有`invoke_api`、`network`和`file_write`宿主权限，权益及商品契约仍会逐次检查。
- 供应商固定HTTPS端点、双方约定的provider和binding_id、操作清单、独立连接密钥文件。文件格式为`{"key_hex":"已获准连接密钥的十六进制文本"}`；不把真实密钥放进商品或模型提示。该密钥不是上游API业务密钥。
- 供应商自行保存获准商品发行白名单并在线核对原操作；签名不代表付款或资源许可。没有供应商许可、生产接入授权或真实支付资格时仅做隔离测试。

按[配置示例](api-connections.example.json)填写配置。示例域名、编号均为占位符，不能直接运行。相对路径以配置文件目录为基准；生成后固定为原账本绝对路径。每个提供方配置一次，多个获准任务共享同一份次数账本，最多32个提供方和128条任务连接。同一买方凭据在各提供方使用同一用途。

```powershell
python -B -m ai_supermarket.api_connections prepare --config C:/market/connection-plan.json --directory C:/market/api-connections
python -B -m ai_supermarket.api_connections check --directory C:/market/api-connections
python -B -m ai_supermarket.http_server --database C:/market/market.sqlite --identities C:/market/identities.sqlite --budget C:/market/budget.sqlite --enforce-task-budget --api-connections C:/market/api-connections --port 8765
```

`prepare`先验证完整配置及已有任务授权，再创建全新目录，保存连接配置、私有连接文件、摘要绑定和每个提供方独立次数库。不请求供应商、不生成凭据、不修改任务授权。重复准备原目录拒绝；失败留下的部分目录须保留检查，不能靠刷新或换目录重置用量。此命令只用于尚未运行该连接的首次初始化，不是账本迁移工具。

`check`仅在本机核对配置、原账本和任务；不联网、不启动、不证明供应商连通或数据许可。`serve`通过原HTTP启动器开启已配置API路由；省略`--api-connections`时原行为不变。需要已有`--budget`及`--enforce-task-budget`。默认监听本机；跨机监听仍遵循原TLS和Host限制，本版没有修改生产部署。

## 运行与交付

模型继续使用[现有API任务入口](api-remote.md)：搜索、核对报价/许可、取得免费或已付费权益、执行一次、接收结果与许可证、继续完成用户成果及提交原收货回执。新配置不增加模型工具或要求模型读取整份目录。真实收费采购还需配置已获准钱包/采购宿主，本启动参数不启用它，也不自动续购。

每次授权检查原身份、任务预算状态和配置/密钥摘要；买方策略变化、任务撤销或私有文件变化停止后续调用。启动时缺少、空置或无表的原次数库拒绝；沿用[原账本保护](api-quota.md)。已完成结果重启后复用，未知调用只查询原供应商记录，不重新派发。后端业务错误仍按供应商服务规则处理。

准备目录包含私有材料和运行结果，不随源码包发布。维护人员要保护访问、备份及留存。摘要可发现与原保存内容不一致，不是签名或防篡改存储；用合法旧备份替换全部文件不能由本机制自动辨别。若需迁移、轮换凭据、新增任务或改变端点，保留原库及未决记录，另做受控变更；当前没有自动迁移或热更新。

验收须包含实际网络交付、结果及许可证、原操作回执和重启不重复消费。内部原创夹具验证与真实供应商商业联调分开记录，不能把启动成功当作用户成果或收费闭环完成。

v0.127修复：`/health/ready`和恢复校验现在识别原API操作、使用清单及客户收货记录，核对字段、摘要、市场内关联和原发行。正常调用及重启后可继续报告`ready`；格式损坏、未知元信息、回执与原交付不符仍拒绝。配置启动也复用同一检查，不再使用单独的结构检查替代它。历史记录有效不等于原身份仍可调用，运行时权限和权益仍逐次核验。

当前恢复边界：市场/身份/预算联合快照会保留上述API元数据；恢复副本仍先隔离、撤销旧凭据并暂停预算。它不包括市场连接目录中的次数库、供应商操作库、私有配置和结果文件，不能称为完整API灾备。恢复运营者还须保留、核对这些原状态与外部执行事实；不得初始化空次数库接续旧权益，也不能仅凭市场元数据重新派发。v0.131已接续客户端文件收货与渠道履约历史，历史路径绑定仍不自动重绑到恢复后的采购宿主，见[恢复范围](recovery.md)，不作全链路恢复完成声明。
