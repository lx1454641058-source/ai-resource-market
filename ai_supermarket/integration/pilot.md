## 失败诊断的范围

v0.33的`failure.json`在捕获模型进程故障时附带`model_diagnostic`，格式为`codex-process-diagnostic-1`。错误类别区分`model_timeout`（等待超时）、`model_start_failed`（无法启动）、`model_process_failed`（非零退出）、`model_output_missing`（没有输出文件）、`model_completion_missing`（缺少有效完成事件）。其他异常仍沿用原错误处理，不保存任意异常正文。

摘要只计数五类控制事件：thread.started、turn.started、turn.completed、turn.failed、error，记录其中最后一类及进程退出码、坏行数量和是否截断。扫描前1,048,576字节或字符，单行超过65,536字符则跳过；这限制诊断解析范围，不是对子进程全部输出的内存上限。正文、stderr、账户/会话标识、命令行和提供商自由文本均不写入诊断。

看到turn.completed也不能把一个超时请求当成完成或费用已知：`completion_verified`、`usage_verified`、`retry_authorized`均为false，原未知计量及预留继续保留。没有事件只表示没有可用事件；不能推断登录错误、网络故障或零费用。该诊断不会补回v0.32未保存的事件，也不会自动重试、延长等待或扩大授权。

## 准备与执行命令

只准备材料，不调用模型、不读取登录密钥、不安装软件：

```powershell
python -m ai_supermarket.pilot prepare --directory work/pilot-review-UNIQUE
```

必须使用新目录，已有目录拒绝覆盖。proposal.json包含任务、配置、目录与源码摘要；review.json列明调用、等待、数据与费用边界。正文完整性也会检查。

真实调用需要先取得针对该proposal_hash的明确授权，不能把此说明、自动续跑、软件预留或approved:false改为true当授权。授权后由受信操作方执行：

```powershell
python -m ai_supermarket.pilot execute --directory work/pilot-review-UNIQUE --proposal-hash REVIEWED_HASH --approval-ref ACTUAL_APPROVAL_REFERENCE
```

执行参数只是记录批准依据，不验证批准人身份、不增加账户权限。任何源码、目录或任务变化使旧方案失效，需要重新准备与确认适用授权。真正执行前还要核当前账户可用模型与工具行为；认证失败停止，不自动登录、切换模型或修改配置。

`execution/`目录的原子创建用于领取整个试点，确保多进程只启动一次。进程崩溃、调用未知、额度不足或结果写入失败后，不可删除该目录重跑。先核调用记录及两本账，再决定单独的恢复方案；本程序无自动重试或自动重放模型正文。

## 产物与检查

执行后每组保存Markdown正文、JSON检查与用量记录；原调用响应单独保存，授权引用、调用领取和两本账仅在本地execution目录。只有本试点的虚构数据会出现在产物中；仍按普通本地文件管理，暂不承诺匿名化或自动清除。

自动检查只判断必需字面事实、最少标题和占位符，全部通过也保留最终质量unknown。错误金额、虚构访谈、错误因果或不合理建议仍可能逃过这些检查。检查记录是必要条件结果，不是商品认证。

独立复核使用[评审表](../pilots/reviewer-guide.md)。没有真实复核人接收之前，不生成“质量通过”或“提高质量”结论。当前顺序固定、每组单次、样本公开，无随机化和统计检验；结果只能诊断此次接入和行为，正式收益实验继续使用主计划冻结门槛。

## 停止及费用核对

无效选品、完成事件歧义、输出格式错误、超时、账本/文件错误或调用次数/等待额度用尽，立即停止后续动作。已发生调用仍可能收费，未知预留不自动清零。遇到暂停不会假装已停止外部已准入推理；参见[模型计量说明](codex-measurement.md)。

发生供应商账单争议时由实际账户责任人处理；费用引用不是验签凭证。当前没有付费商品或支付结算操作，不能据此宣称已经商业上线。
